# 短信与服务号通知通道配置发布记录

系统设置已新增“短信与服务号通知通道”配置面板。站内通知继续作为基础通道；短信与服务号均为可选补充，通道配置、密钥和模块开关均仅限超级管理员维护。

| 通道 | 已发布能力 | 当前投递边界 |
|---|---|---|
| 站内通知 | 始终保留。 | 不依赖外部服务，业务办理不会因外部通知失败回滚。 |
| 短信 | 可选阿里云短信或腾讯云短信，保存服务商、模块、签名、模板编号和加密密钥字段。 | 用户尚在申请腾讯云短信，且尚未填入审核通过的签名、模板和密钥；系统不会伪造连通性或对外发送。 |
| 服务号 | 增加总开关和模块级开关。 | 服务端默认关闭；即使管理员勾选模块，也仅允许当前明确识别的用户即时登录成功事件。运输、日结、绑定后推送、范围提醒和其他持续状态会记录为跳过，并继续使用站内通知或未来已配置的短信。 |

阿里云与腾讯云官方 SDK 已随自建服务器生产包归档。配置密钥使用既有 AES-GCM 加密托管；设置列表、历史版本、前端页面和审计日志均不返回明文。通知配置写入具有版本保护和发布审计。

已通过 `pnpm verify:release`：类型检查、553 项测试（含 1 项受控跳过）、前端构建、自建服务器构建、迁移卫生和生产依赖审计均成功；生产依赖审计为 0 critical / 0 high / 0 moderate / 0 low。正式服务器已按 `release/current` 原子切换发布，历史前端分包保留，服务 active，正式 HTTPS 首页及后台路由均返回 HTTP 200。

后续在腾讯云短信审核完成后，由超级管理员在该面板填写密钥、签名和模板编号；系统必须在真实服务商回执成功后才可将短信通道标记为已投递。
