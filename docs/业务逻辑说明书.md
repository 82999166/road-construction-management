# 道路施工承包管理系统：业务逻辑说明书

**文档目的：** 说明当前系统中业务单据如何创建、流转、审核、通知、审计和限制修改。本文描述的是服务端规则，而非仅前端按钮行为。

## 1. 统一业务原则

系统以“项目范围 + 岗位角色 + 单据状态 + 审计留痕”为通用规则。业务数据先判断登录身份和项目/组织范围，再判断角色是否启用、授权是否有效，最后执行状态机和写入操作。通知、OCR、外部服务调用失败不得回滚已成功写入的核心业务；失败结果必须可审计。

| 规则 | 业务含义 |
|---|---|
| 草稿优先 | 现场记录可先保存草稿，后续补全、提交或审核 |
| 状态受控 | 已审批、已结算、已锁定等终态不能通过前端直接回退 |
| 项目隔离 | 查询和写入须落在授权项目、部门或组织范围内 |
| 最小通知 | 服务号消息不携带身份证、银行卡等敏感个人信息 |
| 操作审计 | 关键对象均记录操作者、目标、动作、时间和摘要 |

## 2. 人员、角色与终端访问流程

管理员创建或编辑普通管理人员时，可维护账号状态、项目/部门范围、岗位角色、角色有效期和登录方式。登录方式为 PC、手机或双端，认证和受保护接口的服务端中间件会检查当前请求终端，避免仅靠前端隐藏菜单实现限制。

角色解析同时检查：角色启用状态、授权状态为 active、有效起止时间、项目/组织范围。角色被停用后，既有历史授权不再授予超级后台、菜单或项目数据访问。

## 3. 施工日报流程

施工日报用于记录施工日期、作业区域、天气、工作内容、安全事项、问题和进度。状态流转为：

```text
draft → submitted → approved / rejected → locked
```

草稿或退回记录允许受权限控制的修改；审批/锁定后的记录不得任意回退。日报创建、修改和关键状态改变通过统一通知层向主管或相关岗位投递，投递失败只记审计，不撤销日报写入。

## 4. 运输、装卸刷卡与结算流程

运输趟次以车辆、司机、项目、起止点、里程、方量/重量和运价规则为基础。运价由服务端按阶梯规则计算，不能由客户端提交最终金额覆盖。

```text
draft → submitted → verified → settled
                 ↘ void

装土刷卡确认 → 卸土刷卡确认 → 异常复核（如有）
```

装土事件必须先于卸土事件；重复、乱序、未绑卡或停用卡只产生可复核事件，不改变运输趟次。刷卡事件带幂等键，网络重传不会重复确认。装土/卸土成功后可按司机和主管范围发送服务号消息。

## 5. 射频写卡流程

```text
登记写卡器 → 绑定车辆卡 → 准备写卡 → 物理写入 → 确认成功/失败
```

系统将车牌、车型、货厢方式、司机姓名和电话组成最小业务载荷；敏感联系电话以加密方式保存，卡 UID 使用指纹与掩码保存。`prepared` 写卡任务不等于已写入物理卡，只有管理员确认后才成为 `confirmed`；失败任务保留原因和审计。当前硬件协议为预留适配层，不允许浏览器直接无审计写卡。

## 6. 采购、劳务与机械流程

采购申请、订单、劳务工资单和机械成本均遵循草稿—提交—审核—结算/发放的原则。具体角色在其项目范围内发起，项目负责人、财务主管、会计或相应管理岗位审核。已结算/已发放记录受终态保护；可维护记录需要保留修改理由和审计。

机械成本可按月租、日租、小时、台班等规则计算，成本项目包括油料、维修、加班、进退场等。劳务工资关联人员、考勤和工资期间，避免跨项目直接操作。

## 7. 计量申报与项目收方流程

项目收方用于项目部提交现场工程量、位置、方法、证据和复核意见，并可与计量申报建立关联。

```text
draft → submitted → reviewed → locked
                 ↘ rejected / returned
```

收方记录要求项目范围校验，可关联影像、OCR、坐标和水印证据。锁定后不得无审计修改；计量申报和审核通知沿项目岗位范围投递。

## 8. 财务、发票与每日会计日结流程

财务流水记录收入或费用方向、费用类别、发生日期、金额、来源单据、证据和结算状态。发票台账关联项目和可选财务流水，维护发票类型、号码、交易方、税额、验证状态、作废/红冲原因。

每日会计日结按项目与业务日固化：收入、费用、记录数、发票数、发票金额和快照哈希。日结用于打印和装订；封存后的日期应禁止未经审计的底层财务流水修改。当前数据接口和后台汇总已实现，发票录入与标准打印版式仍需完成。

## 9. 影像、OCR 与证据逻辑

移动施工、劳务、机械、运输、采购、计量和财务页面可通过统一“现场拍照”入口进入水印相机。系统带入业务来源和项目上下文，上传后保存文件对象引用、OCR 结果、时间、坐标和水印数据。OCR 仅用于辅助录入，必须由用户人工补全、确认后才进入正式业务记录。

## 10. 认证服务号通知与每日汇总

通知收件人首先可由业务调用明确指定；否则系统沿组织树寻找主管，并追加同项目/组织范围内的项目、施工、运输和财务管理角色。服务号投递按幂等键避免重复，记录发送、失败、跳过、错误码和尝试时间。

每日项目汇总聚合施工日报、财务、计量和运输指标。管理员可在后台设置推送时间、预览和立即执行；Heartbeat 回调依据持久化任务 UID 执行，并为每个项目/业务日保存运行审计，防止重复投递。

## 11. 当前风险与交付边界

| 项目 | 当前边界 |
|---|---|
| 服务号员工绑定 | OAuth 方式受新版网页授权入口影响；扫码/口令/审核绑定正改造，未完成前不能作为生产验收结论 |
| 群发消息 | 需要审批、收件人范围和投递审计的专用发布流程，当前未完成 |
| 射频硬件 | 软件安全流程已具备，厂商协议未接入 |
| 财务打印 | 日结审计数据接口已具备，标准会计打印版式与实物装订流程待补齐 |
| 真实通知验收 | 需在模板、绑定和事件回调配置完成后，用真实关注账号验证 |

> 本系统的“审核通过、通知发送”模式保证业务状态以数据库成功写入为准；外部微信投递失败不会把已通过的业务单据退回，但会留下可追踪的失败记录。
