# 服务号业务通知模板可用性矩阵

本矩阵依据微信官方模板消息运营规范及接口说明编制。模板消息只能用于用户接受服务后、由用户触发的即时通知；模板标题、字段和实际服务场景必须一致，不能把服务号关注或绑定视为持续推送授权。[1][2]

> 微信官方明确：模板消息是“用户触发后的通知消息”，不允许在用户未操作或未同意接收前主动下发；车辆出行类、频率过高的提醒和群发推广类通知属于不允许场景。[1]

## 一、可以优先在模板库检索并申请的场景

以下是**模板库搜索关键词**，不是保证存在或已经审核通过的模板标题。每个场景都必须由同一收件人在服务号内主动发起操作后，立即返回对应结果；系统不能将它们改作后台事件自动推送。

| 系统业务 | 用户主动服务号操作 | 可检索模板关键词 | 可发送内容 | 接入前置 |
|---|---|---|---|---|
| 登录与身份 | 用户在服务号网页完成登录、绑定或安全验证 | 登录提醒、资料变更通知 | 本人登录/绑定是否成功、操作时间、结果 | 仅本人；立即发送。 |
| 司机运输查询 | 司机在服务号内点击“查询本次刷卡结果”或“查询今日运输” | 查询结果通知、状态通知 | 当前运单号、车辆、装/卸状态、查询时间 | 必须由司机本人点击查询；不在刷卡后后台自动发。 |
| 司机服务确认 | 司机在服务号内主动确认签收、查看结算或申请资料变更 | 状态通知、资料变更通知、服务结果通知 | 本人提交/确认是否成功、处理状态、时间 | 必须把网页操作与通知一对一关联。 |
| 管理员服务操作 | 管理员在服务号内主动提交一项办理操作并立即获得结果 | 申请结果通知、审核结果通知、状态通知 | 本次提交是否成功、单号、当前状态 | 不可用于把后台审批变化事后群发给多人。 |
| 现场打卡 | 人员在服务号内主动完成签到（如该服务实际接入） | 签到通知、打卡结果通知 | 本人签到结果、时间、地点说明 | 仅限本人即时操作；不能代替考勤日报推送。 |

## 二、当前不能用服务号模板自动外发的场景

| 当前系统事件 | 结论 | 原因与替代路径 |
|---|---|---|
| NFC 装土、卸土、刷卡开票成功 | 不可自动发送给司机 | 属于后台运输状态变化；“渣土运输通知”已被平台以非即时用户操作为由驳回。保留现场回执、司机服务号查询页、站内审计；待短信审核后可选择短信。 |
| 运输日结、车辆结算、付款状态 | 不可自动发送 | 后台汇总/结算事件不等于收件人在服务号内即时操作；不能将绑定关系当作推送授权。 |
| 柴油登记、价格异常、机械成本、库存变动 | 不可自动发送 | 是后台业务状态或管理预警；应使用站内通知、后台待办或经审核短信。 |
| 施工日报、计量审核、分包、合同状态变化 | 默认不可自动发送 | 除非收件人刚在服务号内主动提交或查询该事项，并使用与即时结果一致的合规模板；否则仅保留站内通知。 |
| 工资、财务流水、审批、回款、付款提醒 | 默认不可自动发送 | 涉及频率、敏感性和事务时点；需要合规的实际服务场景及模板审核，当前保持站内通知。 |
| 系统连接失败、权限变更、安全告警 | 不可通过服务号模板群推 | 是管理员运维告警，不属于用户接受的即时服务；使用后台审计/站内告警。 |

## 三、后续模板库检索与接入顺序

首先在认证服务号对应行业类目下检索“登录提醒”“资料变更通知”“查询结果通知”“状态通知”“服务结果通知”“签到通知”。选中候选模板后，需逐一核对标题以“通知”或“提醒”结尾、字段可映射业务编号/结果/时间、示例不包含品牌或营销语，并以服务号网页中的真实用户动作完成一次测试。[1]

“运输通知”“渣土运输通知”“车辆出行通知”“每日结算通知”“到期提醒”“管理员通知”“系统通知”等关键词不再作为申请方向：它们容易被视为车辆出行、群发、后台提醒或高频骚扰场景，与官方规范不符。[1]

系统侧在未获得审核通过的具体模板编号前，不会重新开启运输、柴油、结算、合同、计量或风险事件的服务号自动外发。服务号投递审计仍保留跳过原因，站内通知和现场回执继续保障业务可追溯性。
