## 2026-07-25：统一身份账号恢复与真实数据验收预检

| 核验项 | 可验证证据 | 结论 |
| --- | --- | --- |
| 密码与恢复责任边界 | 系统仅使用统一 OAuth 会话，不保存企业密码。登录页和移动端个人中心均只跳转 `/api/identity-recovery`，不提供应用内密码填写、重置或令牌处理。 | 通过代码核验 |
| 恢复地址安全控制 | `server/identityRecovery.ts` 仅允许管理员已发布的公开 HTTPS 地址；拒绝凭据、环回、RFC 1918、链路本地、IPv6 ULA/链路本地与内部主机名，并清除 URL 片段。 | 通过单元测试 |
| 固定跳转与回跳边界 | 恢复入口不读取请求查询参数、不会拼接 `returnTo` 或恢复令牌，只会以 302 跳转至后台已发布的配置地址。身份提供方后续的找回、重置与回跳流程由其自身受控配置；本系统不接收该流程的回跳。 | 通过代码核验 |
| 最小化恢复访问审计 | 入口仅记录“已受控跳转”或“未配置”事件、时间及固定摘要；不记录恢复地址、查询参数、令牌、密码、IP 或用户身份。审计写入失败不会阻断已发布的恢复入口。 | 通过单元测试与代码核验 |
| 真实项目数据验收预检 | `admin.acceptance.realDataReadiness` 仅对超级管理员返回组织、项目、岗位授权、部门业务范围、劳务、考勤、工资单的聚合数量与就绪判断；后台概览卡片仅显示就绪状态及缺口。 | 通过代码核验 |
| 当前数据态 | 当前数据库仅有 1 个组织，项目、授权、部门业务范围、劳务、考勤及工资记录均为 0，因此尚不具备移动端劳务台账、考勤、工资统计和打印视图的完整真实数据复测前提。 | 待外部验收 |

> **外部依赖边界：** 企业身份提供方的账号验证、密码重置实际执行、异常登录识别及相关通知取决于该身份平台的能力和企业侧配置。本系统已完成受控跳转与最小化审计，不应将其表述为已验证的身份平台重置流程。
