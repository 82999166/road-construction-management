# 部门业务授权验收记录

本记录说明道路施工承包管理系统中“每个部门登录后仅管理相应业务”的实现边界、配置方式与验证结果。系统继续使用既有统一 OAuth 身份认证；部门并不拥有独立的本地密码或独立登录入口。用户完成统一身份认证后，服务端依据其有效的部门、岗位、业务模块和项目范围授权计算实际可办理业务。

## 授权模型

部门业务授权采用四层交集，避免仅隐藏前端菜单而仍可通过接口访问数据。普通账号必须同时具备有效的岗位分配、所属部门启用的业务模块，以及对应的项目或组织数据范围；任一条件不成立时，服务端返回拒绝结果。超级管理员仍保留受控的全局范围，但移动工作台会明确显示其“超级管理员（全局业务授权）”来源，避免与普通部门成员混淆。

| 授权层 | 持久化或来源 | 生效条件 | 系统行为 |
|---|---|---|---|
| 统一身份 | OAuth 会话 | 会话有效 | 仅作为用户身份来源，不提供本地密码登录。 |
| 岗位分配 | `userRoleAssignments` 与角色目录 | 账号、角色、有效期均有效 | 决定用户可办理的业务动作基础能力。 |
| 部门业务范围 | `departmentBusinessScopes` | 部门与业务模块均启用 | 决定部门可以办理哪些标准业务模块。 |
| 项目数据范围 | 岗位授权中的项目或组织范围 | 项目/组织范围与当前模块授权求交集 | 限制可查询、录入、审批或更新的项目数据。 |

> 对于普通业务账号，项目范围不再仅由“账号拥有过某个岗位”推导，而是严格来自**同一条岗位—部门—业务模块授权记录**。这可以阻止用户通过同时拥有不同部门的多个岗位而借用另一岗位的项目范围。

## 已接入的业务边界

后台超级管理员可在组织与人员权限管理中维护部门业务范围，并为业务人员绑定启用的部门或项目部。劳务工资、机械管理、运输管理、采购仓储、工程计量、财务成本及现场取证等接口均叠加岗位、部门模块与项目范围校验；移动工作台只展示服务端投影后的菜单，不能通过客户端手工增加入口绕过接口鉴权。

| 场景 | 用户可见体验 | 服务端强制边界 |
|---|---|---|
| 普通部门成员 | 显示当前部门、已开通的部门业务与对应菜单 | 业务过程必须同时满足岗位、部门模块和项目范围。 |
| 未配置业务部门或模块 | 保留消息等通用入口，并显示“尚未获分配业务岗位”空状态 | 业务路由拒绝访问，不把空范围解释为全量范围。 |
| 多部门、多岗位成员 | 菜单为岗位和部门模块的交集 | 单个模块的项目范围只能取该模块可办理岗位所属部门的授权记录。 |
| 超级管理员 | 明确显示“全局业务授权”提示 | 服务端保留管理职责所需的全局范围，普通用户无法伪造该角色。 |

## 管理配置步骤

管理员应先建立部门或项目部，再为部门启用对应标准业务模块，最后为人员分配岗位、部门和项目范围。变更后，用户刷新工作台即可获得新的服务端菜单投影；撤销部门模块、停用部门、岗位过期或移除项目范围后，相关接口在下一次请求时立即重新计算并拒绝无效访问。

系统不写入模拟部门、模拟人员、模拟项目或模拟业务单据。实际启用前，应由超级管理员在真实组织与项目范围中完成授权配置，并使用获授权账号进行验收。
