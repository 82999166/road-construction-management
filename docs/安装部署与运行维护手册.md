# 悦信云智管道路施工承包管理系统
## 安装、部署与运行维护手册

**适用版本：** 当前 React、Express、tRPC、Drizzle 与 MySQL 自建部署版本。  
**适用对象：** 具备服务器、数据库和域名管理权限的系统管理员。  
**安全原则：** 本手册只说明变量名称、目录结构与操作顺序，**不记录、粘贴或截图服务器地址、账号、口令、令牌、数据库连接串、AccessKey、Cookie 或证书私钥**。

> 生产发布必须遵守“**先验证、后打包；先隔离、后切换；连续健康检查通过后才保留版本**”的顺序。代码版本可通过 release/current 切换回退；数据库业务数据、系统设置和对象存储文件不会随代码回退。

---

## 1. 系统架构与部署边界

系统前端为 React + Vite，服务端为 Express + tRPC，数据访问由 Drizzle 驱动 MySQL。数据库存储业务事实与配置元数据；影像和附件仅保存对象存储引用，不能以应用服务器本地目录替代对象存储。生产环境使用 HTTPS 反向代理转发到 Node 应用，应用再访问 MySQL、对象存储和已发布的外部业务配置。[1] [2]

| 层级 | 组件 | 责任 | 维护要求 |
|---|---|---|---|
| 边缘层 | 宝塔 Nginx / HTTPS 站点 | TLS、反向代理、SPA 深链、静态资源缓存 | 仅修改实际生效的站点配置；不要启动另一套 Nginx 抢占端口 |
| 应用层 | Node.js + systemd 服务 | tRPC、权限、状态机、审计、文件代理 | 使用独立服务名、独立运行目录与受限环境文件 |
| 数据层 | MySQL | 组织、项目、人员、业务单据、配置与审计 | 先备份再迁移；禁止用代码发布替代数据恢复 |
| 存储层 | 阿里云 OSS 或已配置对象存储 | 照片、票据、证据对象 | Bucket 与受限 RAM 权限最小化；密钥只在后台加密保存 |
| 集成层 | 服务号、短信、OCR 等 | 受系统设置发布控制的外部调用 | 配置草稿须测试、发布并留存审计；失败不回滚已成功业务单据 |

### 1.1 建议运行环境

| 项目 | 建议要求 | 核查命令 |
|---|---|---|
| 操作系统 | 受支持的 Linux 长期维护版本 | `cat /etc/os-release` |
| Node.js | 与项目构建环境一致的 Node 22 LTS | `node -v` |
| pnpm | 项目锁定的 pnpm 10.15.1 | `pnpm -v` |
| MySQL | MySQL 8.x，字符集 `utf8mb4` | `mysql --version` |
| 内存与磁盘 | 预留构建、回滚包、日志和备份所需空间 | `free -h`、`df -h` |
| 进程托管 | systemd | `systemctl --version` |
| 反向代理 | 已实际启用的宝塔 Nginx | 在宝塔站点页与 `nginx -T` 中核对 |

> 对已有生产服务器，**不要**因为部署本系统而重装 MySQL、重启系统 Nginx、删除历史静态资源、替换其他网站根目录或修改防火墙策略。新系统必须使用独立应用目录、独立数据库与独立服务。

## 2. 上线前准备

### 2.1 建立目录与服务账号

新服务器建议创建独立的非 root 运行账号，例如 `yxapp`，并由 root 或受控运维账号负责发布。现网历史服务如尚以 root 运行，应先完成停机窗口、目录权限和回滚演练后再迁移，不能与功能发布混合进行。

```bash
sudo useradd --system --create-home --shell /usr/sbin/nologin yxapp
sudo install -d -o yxapp -g yxapp -m 0750 /opt/yx-cloud-management/app/releases
sudo install -d -o yxapp -g yxapp -m 0750 /opt/yx-cloud-management/shared
sudo install -d -o yxapp -g yxapp -m 0750 /opt/yx-cloud-management/logs
```

### 2.2 创建数据库与最小权限账户

在数据库管理工具或 MySQL 控制台中创建**独立数据库**和只供本系统连接的账户。不要复用其他网站数据库账户，也不要给业务账户授予全局 `GRANT ALL ON *.*` 权限。初始建库后记录数据库名、服务地址和账户到密码管理器；连接串只写入服务器受限环境文件。

```sql
CREATE DATABASE yx_cloud_management
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

CREATE USER 'yx_app'@'127.0.0.1' IDENTIFIED BY '请在密码管理器生成的高强度口令替换';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP
  ON yx_cloud_management.* TO 'yx_app'@'127.0.0.1';
FLUSH PRIVILEGES;
```

> 上例中的用户名、数据库名可按实际标准调整。示例口令不能用于任何环境。生产数据库账户的密码不得提交到 Git、写入 `todo.md`、放进截图或通过即时通信传递。

### 2.3 编写受限环境文件

创建独立环境文件，例如 `/opt/yx-cloud-management/shared/runtime.conf`，并将权限收紧为仅服务账号和受控管理员可读。常见变量如下；以当前 `server/_core/env.ts` 和已发布的系统设置为准。[1]

| 变量类别 | 示例变量名称 | 用途 | 管理方式 |
|---|---|---|---|
| 基础运行 | `NODE_ENV`、`PORT`、`DATABASE_URL`、`JWT_SECRET` | 应用启动、数据库连接、会话签名 | 仅服务器受限环境文件 |
| 身份认证 | `OAUTH_SERVER_URL`、`VITE_OAUTH_PORTAL_URL` | 已启用的统一身份认证能力 | 与身份服务端一致配置 |
| 应用标识 | `VITE_APP_ID`、`VITE_APP_TITLE`、`VITE_APP_LOGO` | 前端身份与显示 | 不包含私钥或访问令牌 |
| 临时入口 | `TEMP_ADMIN_ENABLED` | 仅用于受控应急恢复 | 生产已有正式管理员时保持关闭 |
| 内部平台服务 | `BUILT_IN_FORGE_API_URL`、相关密钥 | 平台托管能力 | 按平台规则安全注入，不写入源码 |

```bash
sudo install -o root -g yxapp -m 0640 /dev/null /opt/yx-cloud-management/shared/runtime.conf
sudoedit /opt/yx-cloud-management/shared/runtime.conf
sudo chmod 0640 /opt/yx-cloud-management/shared/runtime.conf
```

环境文件至少应包含：

```dotenv
NODE_ENV=production
PORT=18080
DATABASE_URL=mysql://yx_app:受保护密码@127.0.0.1:3306/yx_cloud_management
JWT_SECRET=使用密码管理器生成的高熵随机值
TEMP_ADMIN_ENABLED=false
```

### 2.4 安全基线核对

在首次发布或服务器迁移前完成以下检查。未完成时可部署到隔离预发布环境，但不应宣称生产验收通过。

| 检查项 | 通过条件 |
|---|---|
| 域名与 HTTPS | 正式域名已指向正确站点；证书链受信任；HTTP 自动跳转 HTTPS |
| SPA 深链 | `/`、`/login`、`/admin/login`、`/admin/*`、`/mobile/*` 不返回 Nginx 404 |
| 应用健康 | Node 服务仅监听本机端口，反向代理可访问首页 |
| 文件权限 | 环境文件、备份目录、日志目录和 release 目录不对其他用户可写 |
| 数据库 | 已完成一次可验证备份；迁移列表与数据库迁移日志一致 |
| 身份与账号 | 正式超级管理员账号已建立；临时超级管理员入口保持关闭 |
| 外部配置 | OSS、服务号、短信或 OCR 仅在后台保存测试并发布后启用 |

## 3. 初次安装

### 3.1 获取源码与依赖

以下命令在独立工作目录执行。若使用 GitHub，建议使用受保护主分支和部署专用只读密钥；不要把 GitHub 访问令牌写进远端 URL。

```bash
sudo install -d -o yxapp -g yxapp -m 0750 /opt/yx-cloud-management/src
sudo -u yxapp git clone <您的受控源码仓库地址> /opt/yx-cloud-management/src/current
cd /opt/yx-cloud-management/src/current
corepack enable
corepack prepare pnpm@10.15.1 --activate
pnpm install --frozen-lockfile
```

### 3.2 检查迁移并初始化数据库

在空数据库首次部署时，先检查迁移卫生，再生成并执行迁移。对已有生产数据库，任何迁移前均必须先完成可恢复备份并人工审阅 SQL；不能以“重新初始化数据库”处理生产故障。

```bash
cd /opt/yx-cloud-management/src/current
pnpm db:check

# 仅在新库或已审阅的维护窗口执行
pnpm db:push
```

`pnpm db:push` 会先执行迁移卫生检查，再生成和执行 Drizzle 迁移。若命令报告迁移不一致，应停止发布，核对迁移文件、迁移日志和备份，不要手工删除迁移记录。[3]

### 3.3 执行发布级验证

```bash
cd /opt/yx-cloud-management/src/current
pnpm verify:release
```

该命令依次执行 TypeScript 类型检查、全量 Vitest、前端构建、自建服务器 CJS 运行包构建、迁移卫生检查和生产依赖审计。构建输出中可能出现前端分包体积提示；只有命令退出码为 `0` 时，才可进入打包步骤。[1]

## 4. systemd 应用服务

### 4.1 推荐服务单元

在新服务器上创建 `/etc/systemd/system/yx-cloud-management.service`。`WorkingDirectory` 必须指向 `current` 符号链接，而非固定某个 release 目录，才能实现原子切换。

```ini
[Unit]
Description=Yuexin Cloud Construction Management
After=network.target mysql.service
Wants=mysql.service

[Service]
Type=simple
User=yxapp
Group=yxapp
WorkingDirectory=/opt/yx-cloud-management/app/current
EnvironmentFile=/opt/yx-cloud-management/shared/runtime.conf
ExecStart=/usr/bin/node /opt/yx-cloud-management/app/current/dist/index.cjs
Restart=always
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ReadWritePaths=/opt/yx-cloud-management
StandardOutput=append:/opt/yx-cloud-management/logs/app.log
StandardError=append:/opt/yx-cloud-management/logs/app-error.log

[Install]
WantedBy=multi-user.target
```

加载并启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now yx-cloud-management.service
sudo systemctl status yx-cloud-management.service --no-pager
```

> 正在运行的历史服务如果使用不同的路径、账户或 unit 名称，应沿用其已验证的结构完成一次独立回滚演练后再迁移。不要在业务高峰期直接更改 `User=`、Nginx 端口、数据库账户或服务单元。

### 4.2 健康检查

应用默认应只在本机监听，例如 `127.0.0.1:18080` 或受控本机端口。服务启动后连续检查主页和 systemd 状态；首次启动可能因依赖初始化耗时而短暂不可用，不能看到一次连接失败就立即认定发布失败。

```bash
systemctl is-active --quiet yx-cloud-management.service
curl -fsS --max-time 5 http://127.0.0.1:18080/ >/dev/null
```

建议以连续 3 次、每次间隔 5 秒的 `systemctl` + `curl` 成功作为“服务就绪”判断条件。

## 5. 宝塔 Nginx 与 HTTPS

在**实际生效的宝塔站点配置**中为正式域名配置 HTTPS 反向代理。不要重启系统中另一套未被宝塔接管的 Nginx，也不要覆盖其他站点配置。

```nginx
server {
    listen 443 ssl http2;
    server_name example.com;

    # 使用宝塔申请和维护的证书路径；不得把证书私钥写入源码。
    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:18080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }
}
```

为 SPA 深链保留应用反向代理，不要仅用静态 `try_files` 覆盖 `/admin`、`/login` 或 `/mobile` 路由。发布后至少从公网核验首页、普通登录、超级管理员登录、后台和一个移动业务页面均返回 HTTPS 成功响应。

## 6. 标准原子发布流程

### 6.1 构建与打包

仅在 `pnpm verify:release` 成功后打包。自建服务器部署使用 `dist` 目录中的自包含 CJS 入口，打包时保留 `dist` 顶层目录结构。

```bash
cd /opt/yx-cloud-management/src/current
pnpm verify:release
tar -czf /tmp/yx-release.tgz dist
sha256sum /tmp/yx-release.tgz > /tmp/yx-release.tgz.sha256
tar -tzf /tmp/yx-release.tgz | grep -x 'dist/index.cjs'
```

### 6.2 上传到隔离暂存区

将压缩包和摘要上传至 `app/staging`，先在服务器端重新计算 SHA-256。摘要不一致、包中缺少 `dist/index.cjs` 或不能解压时必须停止，线上 `current` 不做任何改动。

```bash
cd /opt/yx-cloud-management/app/staging
sha256sum yx-release.tgz
tar -tzf yx-release.tgz | grep -x 'dist/index.cjs'
```

### 6.3 解压、切换、验证与自动回滚

以下为逻辑步骤。建议固化为受控发布脚本，仅允许发布账号执行。

1. 记录当前 `current` 符号链接的真实 release 路径为 `PREVIOUS`。
2. 在 `releases/<时间戳>-<说明>` 新建空目录，将暂存包解压到此目录。
3. 验证新目录存在 `dist/index.cjs`；不可在解压过程中覆盖当前 release。
4. 先创建 `current.next -> 新 release` 符号链接，再使用 `mv -T` 原子替换 `current`。
5. 重启应用服务，连续进行 3 次本机健康检查。
6. 连续通过后保留新 release；若超时或服务失败，则将 `current` 原子指回 `PREVIOUS` 并重启服务。
7. 保留至少一个已验证的上一版本及历史前端资源，不要清空旧 release 目录。

示意脚本：

```bash
set -euo pipefail
APP=/opt/yx-cloud-management/app
SERVICE=yx-cloud-management.service
RELEASE="$(date +%Y%m%d%H%M)-release"
PREVIOUS="$(readlink -f "$APP/current")"
TARGET="$APP/releases/$RELEASE"

mkdir -p "$TARGET"
tar -xzf "$APP/staging/yx-release.tgz" -C "$TARGET"
test -f "$TARGET/dist/index.cjs"
ln -s "$TARGET" "$APP/current.next"
mv -Tf "$APP/current.next" "$APP/current"
systemctl restart "$SERVICE"

ok=0
for attempt in $(seq 1 36); do
  if systemctl is-active --quiet "$SERVICE" \
      && curl -fsS --max-time 5 http://127.0.0.1:18080/ >/dev/null; then
    ok=$((ok + 1))
    [ "$ok" -ge 3 ] && exit 0
  else
    ok=0
  fi
  sleep 5
done

ln -s "$PREVIOUS" "$APP/current.rollback"
mv -Tf "$APP/current.rollback" "$APP/current"
systemctl restart "$SERVICE"
exit 1
```

## 7. 数据库备份与恢复演练

生产数据库备份由受控服务器环境执行，严禁放入业务服务器公开目录。项目提供 `pnpm backup:self-host` 与 `pnpm backup:self-host:verify`，用于在已配置的服务器环境中执行完整备份及离线验证。[4] 完整备份的浏览器取件默认关闭；仅在环境管理员启用受控开关后，超级管理员才能在后台经二次确认下载“已验证”的压缩工件。下载必须走同源会话、重新校验清单/大小/工件边界、支持断点续传并写入审计；不得生成公开外链、对象存储直链或在线恢复入口。

| 操作 | 频率建议 | 验收标准 |
|---|---|---|
| 全量数据库备份 | 每日及任何迁移前 | 可生成完整转储、文件非空、校验成功 |
| 备份离线验证 | 每周及重大变更前 | 在隔离环境可读取并完成结构/记录核验 |
| 恢复演练 | 重大版本与迁移前 | 仅对隔离库操作；不覆盖生产数据库 |
| 对象存储抽查 | 每月 | 随机核验受控预览、历史对象前缀和权限 |

> 代码检查点不是数据库备份。进行“代码回滚”前，必须先确认问题不涉及已写入的业务数据或配置；涉及数据修复时，应按审计、备份和维护窗口流程单独处理。

> 完整备份包含生产业务数据。领取人须保存至受控加密介质，不得转发、上传个人网盘或留存至非受控电脑。恢复只能在隔离演练库由数据库管理员执行；详细的专用服务账号、目录权限、最小 sudo 授权、开关和 Nginx 下载路由要求见 `self-hosted-database-backup.md`。

## 8. 发布后验收清单

| 范围 | 核验动作 | 通过标准 |
|---|---|---|
| 服务 | `systemctl status`、本机健康检查 | 服务为 `active`，连续请求成功 |
| HTTPS | 访问正式首页 | 证书有效、页面资源无动态模块加载错误 |
| 深链 | `/login`、`/admin/login`、`/admin/diesel`、`/mobile/transport` | 均可直接打开，不返回 404 |
| 登录 | 使用正式管理员和普通业务账号分别登录 | 超级管理员进入全局治理；普通账号仅进入授权业务范围 |
| 业务 | 在已授权真实项目查看一条现有记录 | 项目范围、时间、状态和附件权限正确 |
| 打印与导出 | 使用当前筛选范围打印或导出 | 明细来自真实服务端数据、末行合计正确、无原始英文状态枚举 |
| 审计 | 查看最近操作 | 发布相关业务操作与安全事件只保留摘要，不含口令或密钥 |

真实 PDF、照片上传、服务号/短信送达和现场刷卡必须由授权人员使用真实业务记录验收。不得以空白页面、模拟数据、未审核模板或未连接硬件冒充验收成功。

## 9. 常见问题排查

| 现象 | 优先检查 | 禁止做法 |
|---|---|---|
| 页面白屏或动态模块加载失败 | 当前 release、`dist/public/assets`、Nginx 缓存与浏览器控制台 | 删除所有旧静态资源或直接覆盖 `current/dist` |
| `/admin` 或 `/login` 返回 404 | 宝塔实际生效站点的反向代理与 SPA 深链 | 重启系统另一套 Nginx 或修改其他站点 |
| 服务重启后未就绪 | `systemctl status`、应用错误日志、环境文件可读性、本机端口 | 反复强制切换 release 而不等待连续健康检查 |
| 登录提示错误 | 正式账号状态、角色、登录入口、失败限流状态 | 打开临时超级管理员入口或在日志中打印口令 |
| 数据库迁移失败 | 迁移卫生、备份、当前 schema 与迁移记录 | 删除迁移表记录、重建生产数据库 |
| 影像上传失败 | OSS 设置、Bucket Endpoint、RAM 权限、对象前缀与后台“测试 OSS 连接” | 把 AccessKey 放到前端或改用公开目录 |
| 通知未送达 | 后台已发布渠道、模板匹配、收件人授权、通知审计 | 伪造投递成功或让通知失败回滚已成功业务 |

## 10. 运维交接记录模板

每次发布建议记录以下不敏感信息，便于回滚与追溯：

| 字段 | 填写内容 |
|---|---|
| 发布日期与时间 | 中国标准时间 |
| 发布人 | 姓名或工号，不记录口令 |
| 源码版本 | Git 提交短哈希或检查点版本号 |
| 上一 release | release 名称，不含服务器地址 |
| 验证结果 | `pnpm verify:release`、SHA-256、连续健康检查、HTTPS 深链 |
| 数据库操作 | 无 / 已备份 / 已审阅迁移；列出工单号 |
| 回滚结论 | 未回滚 / 已回滚及原因 |
| 待人工验收 | 真实 PDF、现场业务、OSS 或外部通知等 |
