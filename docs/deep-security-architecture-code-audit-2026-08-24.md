# 悦信云智管深度安全、架构与代码审计报告

**审计日期：** 2026-08-24  
**审计方式：** 源码、依赖清单、当前构建入口、正式服务器只读状态、HTTPS 响应头与备份元数据的交叉核对。  
**审计约束：** 本轮未修改业务代码、数据库、服务器配置、服务进程或部署版本；不读取、不展示任何密码、令牌、OpenID、连接字符串或密钥值。

> 本报告只列出已能复核的风险与工程问题。扫描器对历史遗留文件或非当前生产入口的提示，已单独核验；未证实可达的项目不会作为当前生产漏洞提出。

## 一、结论摘要

当前正式系统具备较好的业务安全基础：项目范围验证默认拒绝、关键业务流程已使用条件更新和审计、服务号回调进行了验签、OAuth 状态带签名与有效期校验、敏感服务号配置采用 AES-256-GCM 加密，HTTPS 与数据库备份文件也已实际存在。当前未发现**已证实的匿名 API 认证绕过、当前生产入口暴露的 Telegram Session 解析接口、或跨项目数据读取漏洞**。

本轮优先风险集中在**正式服务器暴露面与运行权限**，而不是道路施工业务规则本身：临时超级管理员入口仍配置在生产环境；应用以 root 运行且没有 systemd 沙箱约束；防火墙对公网开放了大范围端口；同时，前端会展示错误堆栈，服务缺少常用浏览器安全响应头。建议先处理高优先级运维安全项，再安排依赖与代码质量收敛。

| 风险等级 | 已确认数量 | 本轮处置建议 |
|---|---:|---|
| 高 | 3 | 待你确认后优先修复；涉及生产登录入口、系统服务权限与网络暴露面。 |
| 中 | 5 | 作为第二批实施；涉及资源限制、错误信息、限流、浏览器防护头和依赖更新。 |

## 二、已确认问题清单

### 高优先级：建议优先处理

| 编号 | 问题与影响 | 可复核证据 | 建议修复方向 | 风险 / 实施影响 |
|---|---|---|---|---|
| H-01 | **临时超级管理员入口仍在生产环境可配置。** 该入口成功后创建具有管理员身份的 8 小时会话；即使账号只用于初始化，长期保留会扩大高权限凭据暴露面。 | `server/localAuth.ts:11-15,103-107,169-191`；正式运行配置仅核验到 `TEMP_ADMIN_USERNAME`、`TEMP_ADMIN_PASSWORD` 均为“已配置”。 | 在确认现有超级管理员可正常登录后，增加显式的“初始化完成/临时入口禁用”开关，并在生产默认拒绝临时账号登录；保留一次性应急恢复流程和审计。 | **高**。需要先确认现有管理员入口与应急恢复方案，避免误锁定系统。 |
| H-02 | **应用进程以 root 运行，未启用 systemd 隔离。** 一旦 Node、上传解析或依赖发生远程执行漏洞，影响范围会从应用数据扩大到整台服务器。 | 正式服务器只读 `systemctl show yx-cloud-management`：`User=root`，且 `ProtectSystem=no`、`ProtectHome=no`、`PrivateTmp=no`、`NoNewPrivileges=no`。 | 创建专用低权限服务账号；最小化目录读写权限；在灰度验证后启用 `NoNewPrivileges`、`PrivateTmp`、`ProtectSystem`、`ProtectHome` 与能力白名单。 | **高**。需要先盘点发布目录、备份目录、对象存储目录和日志目录的权限。 |
| H-03 | **防火墙对公网开放范围过宽。** 除 80/443 外，还开放了管理面板、多个管理端口及 `1:65000/tcp` 全端口段；若其中任一服务缺少二次认证或存在漏洞，攻击面显著增加。 | 正式服务器只读 `ufw status`：存在多个公网允许端口与 `1:65000/tcp` 规则。 | 先做“端口—进程—业务用途—访问来源”盘点；只保留 80/443 与确有外部需求的端口；管理面板和 SSH 改为固定办公 IP / VPN / 安全组白名单。 | **高**。须先确认设备、宝塔或运维访问实际端口，不能直接关端口。 |

### 中优先级：建议第二批处理

| 编号 | 问题与影响 | 可复核证据 | 建议修复方向 | 风险 / 实施影响 |
|---|---|---|---|---|
| M-01 | **全局 JSON 与表单正文上限为 50 MB，Nginx 上限为 60 MB。** 除影像上传外，普通 API 同样可接收大体积请求；在没有可见应用层限流的情况下，会增加内存和带宽型拒绝服务风险。 | `server/_core/index.ts:38-41`；正式 Nginx 有 `client_max_body_size 60m`。 | 将普通 API 限制为较小体积；仅对证据上传等必要路由放宽；增加按 IP / 会话 / 路由的限流和超时。 | **中**。要与相机水印影像大小及微信回调体积兼容。 |
| M-02 | **本地管理员登录失败限流仅在进程内存中保存。** 重启服务即可清空计数，未来多实例时也不共享。 | `server/localAuth.ts:16-18,30-31,64-69,195-214`。 | 短期：在数据库或系统设置中持久化锁定窗口；长期：接入 Redis 等共享限流存储，并保留安全审计。 | **中**。单实例下风险较低，但不应依赖重启后的自然清零。 |
| M-03 | **生产错误页向用户直接展示 `error.stack`。** 会暴露源码路径、组件名称和依赖调用链，为攻击者提供侦察信息。 | `client/src/components/ErrorBoundary.tsx:24-40`。 | 生产环境仅显示友好错误号；详细栈仅写入受控日志或管理员诊断记录。 | **中**。低兼容风险。 |
| M-04 | **HTTPS 响应未见常用浏览器防护头。** 当前已正确从 HTTP 跳转到 HTTPS，但响应中未见 HSTS、CSP、X-Frame-Options、X-Content-Type-Options、Referrer-Policy 和 Permissions-Policy。 | 正式域名只读 `curl -I`。 | 在 Nginx 先添加低风险头：`X-Content-Type-Options: nosniff`、`Referrer-Policy`、`Permissions-Policy`、`X-Frame-Options`；CSP 需先报告模式验证，避免影响地图、微信与动态分包。 | **中**。CSP 应灰度，其他头通常可先上。 |
| M-05 | **生产依赖存在已知安全公告与升级积压。** 其中 `xlsx@0.18.5` 有公告，但当前代码只见导出，不见解析外部 Excel；`@trpc/server` 公告针对 Next.js App Router，当前使用 Express 适配器，不能作为当前可利用漏洞。仍应统一升级受影响依赖。 | `pnpm audit --prod --json`；`xlsx` 使用点在 `client/src/pages/AdminPage.tsx:394`，未发现 Excel 导入调用。 | 建立锁文件升级分支：优先更新可自动修复的 AWS SDK、axios 链、Express 链、Markdown/Mermaid 链；将 SheetJS 改为受维护替代方案或限制为仅导出；每批运行全量测试与生产构建。 | **中**。依赖升级必须分批，不建议直接执行全量 `pnpm update`。 |

### 2. 状态机与审计链判断

本轮针对运输、柴油、考勤、结算、群发通知、合同与主数据删除做了抽查。近期已修复的考勤状态机目前已通过真实上班/下班打卡和后台台账验收。运输结算、合同状态和群发通知在抽查范围内普遍采用“当前状态条件 + 更新结果检查 + 审计”模式；例如群发通知的确认回执、审核流转与发布锁定均使用条件更新，避免重复确认或并发发布。[1]

未发现应立即停止业务的已证实状态机破坏问题。但 `server/routers/operations.ts`、`server/routers/admin.ts` 等路由规模较大，持续维护成本和回归覆盖压力较高。建议将下一阶段的工程优化限定为**按业务域拆分服务层、统一高影响操作的条件更新辅助函数、并为支付/结算/作废/权限变更建立固定回归矩阵**，不要在无测试护栏下进行一次性大重构。
