# 新微信公众号服务号迁移核验清单

## 迁移原则

旧服务号的已发布配置在新服务号完成凭据校验、模板绑定与受控投递验证前保持不变。切换仅替换服务号应用身份与业务模板配置；固定出口网关域名、签名机制和最小微信 API 路径白名单继续复用，不将其扩展为通用代理。

## 用户需要准备的资料

| 项目 | 必要性 | 说明 |
| --- | --- | --- |
| 新服务号 AppID | 必填 | 用于系统配置中的公众号应用身份。 |
| 新服务号 AppSecret | 必填 | 仅通过受控密钥配置输入，不在聊天、文档、日志或代码中保存。 |
| 新服务号合规业务模板 | 必填 | 建议为通用业务进度/待办通知，不使用“审批未通过”这类单一业务语义模板。 |
| 模板页面截图或模板 ID 与字段列表 | 必填 | 用于生成模块映射并校验字段类型/长度，避免微信 `47003` 参数格式错误。 |
| 白名单完成证明 | 必填 | 新服务号后台需将固定出口 `35.237.214.196` 加入 API IP 白名单。 |
| 已关注且完成系统绑定的测试人员 | 必填 | 用于执行一次受控模板投递，不使用未关注账号判断模板可用性。 |

## 系统执行顺序

1. 安全保存新 AppID 与 AppSecret，保持旧服务号配置不变直至新凭据通过校验。
2. 使用固定出口网关请求微信凭据接口，验证新账号 IP 白名单与网关签名配置。
3. 读取已发布的私有业务模板，校验模板可下发且字段映射不含空字段或类型不兼容值。
4. 将合规模板绑定到施工、采购、柴油、运输、机械、劳务、计量、分包、财务和合同模块；若仅有一条模板，则采用经校验的通用字段映射。
5. 对已关注并完成绑定的测试人员发送受控测试事件，核验 `sent`、微信返回消息标识和站内投递审计。
6. 新账号验证成功后停用旧模板映射与旧绑定提示；主业务始终不会因通知失败而回滚。

## 验收边界

> 系统只记录最小化的投递状态、失败码和时间。AppSecret、网关签名密钥、OpenID、授权码、访问令牌和通知正文不写入迁移文档或审计摘要。

新账号尚未具备模板、白名单或关注绑定时，系统会将业务正常入账，并将通知记录标记为配置缺失、未绑定或投递失败；这不等同于业务失败。
