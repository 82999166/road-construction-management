# 道路施工承包管理系统：项目功能说明书

**文档版本：** 代码审计快照  
**适用范围：** 当前 `/home/ubuntu/road-construction-management` 项目  
**说明：** 本文以当前前端、tRPC 路由、Express 回调、Drizzle 数据模型和待办清单为依据；不把计划中或受外部微信配置阻塞的能力描述为已投产功能。

## 1. 系统定位与总体架构

系统面向道路施工承包企业，覆盖项目、组织、人员、施工、劳务、运输、机械、采购、计量、财务、影像取证和消息通知。前端使用 React 与移动工作台，服务端使用 Express、tRPC、Drizzle ORM 和 MySQL/TiDB；业务接口由 `server/routers.ts` 汇总为 `admin`、`construction`、`labor`、`transport`、`machinery`、`purchasing`、`measurement`、`finance`、`evidence`、`messages`、`mobile`、`officialAccount` 和 `dailyDigest` 等模块。

| 层级 | 当前实现 |
|---|---|
| 桌面端 | 统一 `/admin` 管理后台，按角色、项目和部门范围展示工作区 |
| 移动端 | `/mobile` 工作台及施工、劳务、机械、运输、采购、计量、财务、消息、个人中心页面 |
| 服务端 | tRPC 业务路由 + Express 的身份恢复、服务号绑定、每日汇总回调等端点 |
| 数据层 | Drizzle Schema、MySQL/TiDB；关键写入具有审计、条件更新和幂等处理 |
| 通知 | 认证服务号模板消息为唯一业务通知通道；站内消息为降级与审计通道 |

## 3. 运输与射频卡功能

车辆射频卡不把卡 UID、司机电话等敏感信息以明文方式写入普通台账。系统保存卡 UID 指纹与掩码；司机电话在写卡载荷和绑定信息中采取加密保存。后台管理员登记写卡器型号、连接方式和状态，绑定车辆与司机后生成写卡任务；实际硬件写入由管理员确认，当前预留了 USB、串口、网络和人工确认模式，尚未绑定特定读写器厂商协议。

装土、卸土事件具有幂等键和状态校验。未绑定、已停用、乱序或重复刷卡不会推动趟次状态，而会留下异常审计并转人工复核。成功刷卡可向已绑定司机及相关主管发送包含车牌、项目、里程、运费和闭环状态的最小化业务提醒。

## 4. 财务、发票与日结

财务记录按项目、发生日期、收支方向、费用类别、来源单据、证据和结算状态管理。发票台账支持发票号码、代码、交易方、发票类型、金额、税额、验证状态、作废/红冲原因及关联凭证。日结按项目和业务日生成收入、开支、记录数、发票数、发票金额和不可变快照指纹，供打印与会计审计使用。

> 日结封存后应通过状态控制阻止该日底层财务流水被无审计地修改；打印使用服务端产生的日结数据接口，而不是浏览器临时汇总。

## 5. 消息、通知与绑定

系统已退役企业微信 Webhook，业务通知统一使用认证服务号。服务端将 AppSecret 加密保存，并对模板投递记录状态、微信错误码、重试时间和投递结果留痕。移动个人中心展示各岗位可接收的提醒范围；已绑定用户可接收审核、运输、异常、汇总等通知，未绑定时主业务不会回滚，系统保留失败/跳过审计。

当前网页 OAuth 绑定受微信新版平台网页授权域名入口调整影响，扫码事件绑定的数据库与配置基础已建立，但二维码、微信事件回调验签、口令备用和管理员审核尚未完成发布，详见本文第 8 节。

## 6. 权限、范围与审计

权限最终由服务端裁决。角色授权同时受角色启用状态、授权状态、有效期、项目范围和组织范围约束；已停用角色不会继续通过历史授权保留后台、菜单或项目数据访问。后台可维护管理员账号、岗位角色、项目/部门范围和 PC/手机/双端登录方式。

关键写入记录至 `audit_logs`：配置草稿/发布、人员授权、车辆及卡片管理、运输刷卡、施工与财务状态变更、通知投递、日结封存等。高影响状态机使用条件更新、版本号或幂等键降低并发覆盖风险。

## 7. 外部配置与运行前置条件

| 前置项 | 当前状态 | 影响 |
|---|---|---|
| 认证服务号 AppID/AppSecret | 已可在后台加密保存并完成 access_token 连通性校验 | 未配置时无法发送模板消息 |
| 模板 ID、字段映射、跳转地址 | 支持读取服务号私有模板并生成草稿；需发布后投递 | 决定模板通知格式与跳转 |
| API IP 白名单 | 需包含运行环境实际出口 IP | 未加入会导致微信 40164 |
| 消息与事件推送回调 | 扫码绑定改造进行中 | 未完成前不能以扫码事件绑定员工 |
| 射频读写器协议 | 设备台账与人工确认已实现 | 未接厂商协议前不能由网页直接驱动物理写卡 |
| 每日汇总调度 | Heartbeat 调度代码和后台管理已实现 | 需由管理员启用并完成实际运行验收 |

## 8. 明确未完成或需现场验收事项

1. 服务号扫码事件绑定、一次性口令绑定和管理员审核兜底尚未形成可配置、可验证的最终回调端点；当前 OAuth 网页绑定因新版平台域名入口调整不应作为生产主路径。
2. 服务号群发设置、预览、审批发布、收件人范围治理与批量投递审计尚未完成。
3. 具体厂商的射频写卡器 USB、串口或网络协议尚未接入；当前为安全的人工确认写卡流程。
4. 发票录入、项目收方移动端表单、日结打印版式和全部相关测试仍需继续补齐及做真实业务验收。
