# 运输 NFC 支持模块拆分记录

## 拆分范围

为降低 `server/routers/operations.ts` 中运输 NFC 状态机的维护耦合，本次将以下可复用的服务端逻辑抽取到 `server/services/transportNfcSupport.ts`：车辆在途锁、历史未闭环票据保护、最短连续开票间隔、单次刷卡闭环、条件写入结果判断、中国业务日期、风险扫描触发、围栏距离计算与路线快照标准化。

路由层继续负责 tRPC 输入校验、认证、项目范围、岗位权限、现场管理员、设备与地点匹配、审计和通知；支持模块不接收客户端绕过参数，且保持既有错误语义与数据库条件写入保护不变。

| 兼容项 | 核验方式 | 结果 |
|---|---|---|
| NFC 双设备闭环 | 定向回归覆盖设备、地点、身份、在途锁与深链契约 | 通过 |
| 一车一在途保护 | 静态回归同时验证路由委托与支持模块拒绝逻辑 | 通过 |
| 单次刷卡闭环 | 验证最短间隔、真实闭环快照和锁字段清理 | 通过 |
| 发布质量门禁 | `pnpm verify:release` | 通过 |

## 回归适配

历史静态测试曾直接检索路由文件中的实现细节。模块抽取后，这些测试改为同时检查路由的委托关系和独立支持模块的行为契约，避免以文件位置替代业务行为验证。

完整发布级验证通过类型检查、全量测试、标准构建、自建服务器构建、迁移卫生检查与生产依赖审计。构建过程中保留既有大分包和 CommonJS `import.meta` 警告；二者均为既存告警，本次未改变运行时行为。
