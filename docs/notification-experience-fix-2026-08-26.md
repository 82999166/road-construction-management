# 消息详情、刷卡现场回执与通知设置入口修复

本次针对真实使用反馈修复三个移动与后台体验问题，并已发布至正式服务器。

| 反馈问题 | 已发布修复 | 权限与合规边界 |
|---|---|---|
| 管理员点击消息直接跳到运输页面 | 点击消息现先标记已读并打开消息详情；详情展示完整标题、正文、接收时间与关联业务说明，用户再点击“打开关联业务”才跳转。 | 消息列表仍由服务端按当前用户过滤，前端不传递收件人标识。 |
| 司机刷卡后未知是否成功 | 装土/卸土刷卡在服务端确认后显示持久“现场回执”对话框，由现场人员展示给司机；回执明确区分成功、重复确认与需人工复核。 | 不承诺服务号对运输持续状态外发；腾讯云短信审核配置完成后可作为外部司机提醒补充通道。 |
| 短信设置入口不易找到 | “短信与服务号通知通道”从冗长服务号配置区移动到“系统设置中心”标题正下方，进入系统设置即可见，并继续保留懒加载等待提示。 | 仅超级管理员可见；密钥保持 AES-GCM 加密托管，页面不显示明文。 |

新增消息详情、刷卡现场回执和通知设置入口回归测试，并更新既有运输刷卡测试以匹配服务号持续通知的合规降级。`pnpm verify:release` 通过，正式服务器按 `release/current` 原子切换，历史动态分包保留，应用服务 active；正式 HTTPS 首页与后台路由均返回 HTTP 200。未迁移数据库、未修改业务数据。
