# 服务号订阅通知能力核验

## 结论

认证服务号可以使用**订阅通知**，但不能把它当作对所有已关注用户的无条件替代推送。用户必须在服务号图文或已配置 JS 安全域名的网页中，主动点击订阅并授权；一次性订阅只允许对相应通知下发一条消息，长期订阅仅向政务民生、医疗等公共服务领域开放。[1]

因此，悦信云智管可以将“主动订阅后的特定业务提醒”接入服务号订阅通知；现有的采购、柴油、运输、工资、结算等持续状态通知，仍应保留为合规服务号模板消息或站内通知兜底。当前官方模板消息文档仍说明模板消息能力可正常使用，且仅适用于重要服务通知，禁止营销与骚扰内容。[2]

| 通知场景 | 建议通道 | 必要条件 |
|---|---|---|
| 单次、用户主动订阅的到货/付款/业务结果提醒 | 服务号订阅通知 | 认证服务号、已开通插件、适用类目与模板、用户主动订阅。 |
| 持续的运单状态、采购审批、工资与结算状态提醒 | 服务号模板消息 + 站内通知 | 认证服务号、已选用且语义匹配的模板、用户关注/绑定和合规字段映射。 |
| 未关注、未绑定或未订阅的用户 | 站内通知 | 不伪造微信投递成功；保留失败原因与后续绑定引导。 |

发送接口必须在服务器端调用。模板消息接口支持以 `client_msg_id` 做同一接收者十分钟内的防重；现有系统可继续复用业务幂等键和投递审计。[3]

## 后续接入前置

需要在微信公众平台完成订阅通知插件开通、适用服务类目与模板选用，并在已备案的服务号网页中提供用户主动订阅组件。接入后应将用户订阅状态、模板标识、业务事件类型、幂等键和微信回执写入现有投递审计；未满足订阅条件时自动回退站内通知，不能模拟或夸大微信送达结果。
