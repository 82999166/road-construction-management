# 程序安全整改与环境操作清单

本说明记录已完成的**程序代码层**整改，以及由服务器维护方执行的环境项。整改遵循“默认拒绝、最小权限、失败不放行”的原则；未写入任何口令、令牌、数据库连接信息或用户个人信息。

## 已完成的程序整改

| 优先级 | 已完成内容 | 验证方式 |
|---|---|---|
| P0 | 生产环境存在永久超级管理员时，临时超级管理员入口默认关闭；仅 `TEMP_ADMIN_ENABLED=true` 可在受控应急时恢复 | 临时登录、永久管理员存在、显式开关与会话签发回归测试 |
| P0 | 登录失败限流持久化到 `login_rate_limit_states`；仅保存账号主体的 SHA-256 摘要，不保存明文账号或口令 | 服务重启后的锁定窗口回归测试；唯一键与锁定时间索引迁移 |
| P1 | 普通 API 请求体限制为 1 MB；仅三类已验证的影像/证照上传 tRPC 接口可使用 32 MB；公众号 XML 回调保持 256 KB 原始载荷限制 | HTTP 路径分类、请求大小与影像上传接口单元测试 |
| P1 | 增加基础安全响应头、关闭 `X-Powered-By`；维持相机和定位能力，拒绝麦克风、支付与 USB 等无关浏览器能力 | HTTP 安全中间件回归测试 |
| P1 | 生产前端错误边界不再显示技术堆栈；历史浏览器用户对象缓存会自动清理，认证仅依赖受签名、HttpOnly 会话 Cookie | 前端代码审查与认证回归 |
| P2 | 升级 tRPC、Express 4、Axios、AWS S3 SDK、Drizzle ORM、NanoID 与 Streamdown；将未维护的 `xlsx` 替换为维护中的 `@e965/xlsx`，保留后台按需多工作表导出 | 类型检查、后台导出回归、生产依赖审计 |
| P2 | 新增 `pnpm audit:prod` 与 `pnpm verify:release` 门禁；高危或严重生产依赖公告会阻止通过 | 发布门禁实际执行通过，生产依赖审计为 0 high / 0 critical / 0 moderate / 0 low |

> 当前应用层 IP 限流是单实例防护；如果未来扩容为多个应用实例，应将该计数器替换为 Redis 等共享限流存储。账号主体锁定已使用数据库持久化，不受该限制影响。

## 服务器维护方需要执行的环境项

| 顺序 | 操作 | 验证标准 |
|---|---|---|
| 1 | 部署本版本源码与锁文件，并先运行 `pnpm verify:release` | 类型、测试、双构建、迁移卫生与依赖审计全部通过 |
| 2 | 应用 `drizzle/0072_dashing_gateway.sql`；该迁移仅创建登录限流表与索引，不修改现有业务记录 | `login_rate_limit_states` 表存在，且唯一键为 `scope + subjectHash` |
| 3 | 确认至少存在一名可用的**永久超级管理员**，随后保持 `TEMP_ADMIN_ENABLED` 未设置或设为 `false` | 临时入口拒绝登录，永久管理员可正常登录 |
| 4 | 紧急恢复临时管理员时，短时设置 `TEMP_ADMIN_ENABLED=true`、重启服务、处理恢复任务后立即移除该变量并再次重启 | 审计中可追溯应急使用；日常环境不保留该开关 |
| 5 | 应用服务使用非 root 专用账户；目录、私钥、环境文件仅授予该账户最小读写权限 | 服务运行身份不是 root，敏感文件不对其他用户开放 |
| 6 | 防火墙仅公开 HTTPS/HTTP；SSH 仅开放管理来源；应用内部监听端口和数据库端口不直接暴露公网 | 外网只可访问反向代理入口，内部端口不可直连 |
| 7 | 按既有脚本进行一次受控数据库备份恢复演练，记录恢复点、耗时和校验结果 | 备份可恢复到隔离库，关键表结构和抽样记录校验通过 |

## 发布后检查

发布完成后，使用不含真实业务写入的方式验证首页、管理员登录、移动端会话续期、影像上传入口和后台 Excel 导出。对于生产环境，避免用虚构的运输、柴油、工资或合同单据作为验证数据；优先使用健康检查、只读台账查询和受控测试账号。
