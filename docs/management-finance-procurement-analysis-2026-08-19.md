# 管理、权限、采购归档与业务闭环需求分析

## 分析结论

本次分析以当前道路施工承包管理系统代码、已发布的数据模型、服务端路由与既有回归测试为准。并行审查中出现的与其他项目有关的结论未被采信；以下结论仅针对本项目。

| 优先级 | 用户需求 | 当前基础 | 已确认缺口 | 实施边界 |
|---|---|---|---|---|
| P0 | 采购记录管理端完整可见 | 采购订单已保存项目、类别、物资、数量、单价、金额、单据影像、供应商、状态和审计；已确认订单已投影至财务应付 | 管理端订单列表/详情对已关联单据影像、发票附件和字段来源的下钻不够直观 | 增加采购详情抽屉，展示完整字段、多张单据/发票附件、影像预览和审计时间线 |
| P0 | 采购发票与上传效率 | 已有普通采购单据影像上传、金额手动/自动双路径与财务发票台账 | 采购订单尚未明确“是否有发票”默认规则；发票影像/PDF未作为采购订单专属附件；未有统一图片压缩策略和后台可配说明 | 默认“无发票”；支持多张照片/PDF发票附件；服务端限制类型、文件大小和图片最长边，保留原始审计元数据 |
| P1 | 公司管理人员工资设置 | 员工档案可区分公司管理人员，已保存基础薪资及工资口径；工资条、审核、发放和付款审计状态机已存在 | 管理端缺少面向公司管理人员的清晰“薪资标准设置”入口，岗位标准与个人薪资调整/生效期间未形成独立可追溯配置视图 | 在劳务工资工作区新增公司管理人员薪资标准页签；区分岗位建议标准、个人生效标准、津贴/扣款及期间工资条，沿用会计审核和财务付款终态 |
| P1 | 菜单详细功能权限 | 已有部门模块、角色详细权限、项目范围与用户专属授权；合同管理已纳入独立 CONTRACT 模块和统一守卫 | 权限配置的可读性需要提升：菜单、页面和操作的映射不能只以权限码呈现；部分新工具应明确“只读工具”与“业务写入”操作边界 | 在权限管理增加菜单—页面—操作三层矩阵和业务说明；每项权限继续由服务端守卫强制执行，前端仅做菜单投影 |
| P2 | 全业务闭环审查 | 采购、劳务、柴油、运输、机械、计量、分包、合同和财务均已有主要状态机、审计和项目范围校验；采购确认到财务应付已修复 | 仍需将跨模块“业务确认、应付/应收、实际收付、财务总账”的归集规则逐模块登记为可测试的矩阵；基础档案及附件变化需统一核对审计 | 先建立闭环矩阵和自动化回归，再对确有资金性质且已具备权威状态的节点实施幂等归集；不得将合同承诺或未确认成本虚构为真实资金流水 |

## 建议的业务规则

### 1. 公司管理人员工资

公司管理人员工资应在 **劳务工资 → 公司管理人员薪资标准** 中设置，而不是散落在员工编辑窗口。工资标准应有岗位建议值和个人生效值两层：岗位标准用于新人员建议，个人标准用于实际核算；每次变更必须记录生效月份、调整原因和操作人。期间工资条继续沿用“草稿 → 提交 → 会计审核 → 财务付款”的既有状态机，已付款工资不得回写。

### 2. 权限结构

权限采用三层投影：**菜单** 决定是否看到业务入口，**页面** 决定是否读取对应页面数据，**操作** 决定新建、编辑、提交、审核、付款、作废、导出和配置等高影响动作。项目范围、角色详细权限和用户专属授权需要同时在服务端生效；超级管理员仅作为全局治理例外，不替代业务岗位职责分离。

### 3. 采购单据、发票与压缩

采购录入默认“**无发票**”，用户可选择“有发票”。清单/送货单/验收单与发票应当是两类附件：前者证明采购事实，后者证明税务票据。管理端采购详情应展示物资、数量、单价、自动或手动金额来源、供应商、审核/收货/结算状态、单据照片、发票照片或 PDF、关联库存和财务应付/结算记录。

图片上传建议采用“拍照后前端预压缩 + 服务端硬性校验”的两层策略：普通单据和发票照片最长边默认不超过 1920px，JPEG 质量默认 0.80，单张压缩后建议不超过 2MB；PDF 不压缩页面内容，但单文件上限建议 15MB。后台应显示该规则；原始拍摄时间、附件哈希、上传人和业务关联仍需审计留存。参数必须在系统设置可调整，且不影响已经归档的历史文件。

### 4. 财务闭环

财务总账必须区分三类事件：业务应收/应付、实际收款/付款、非资金性质的合同或预算承诺。已确认采购订单目前作为“采购订单应付”出现，实际采购结算单独进入现金流；两者可追溯同一订单但不重复累计。后续同样应对工资、柴油、机械、运输、计量回款和分包结算逐项建立幂等归集规则与回归测试。

## 实施顺序

1. 先完成采购详情、发票选择、照片/PDF附件与压缩策略，解决管理端看不到完整凭证的直接问题。
2. 再完成公司管理人员薪资标准入口与三层权限矩阵，提升日常配置可用性。
3. 最后建立全业务闭环矩阵，逐模块核验业务状态、应收应付、实际资金、审计和异常回滚路径。

> 本分析不以合同金额、预算金额或未审核单据虚构真实财务流水；附件、发票和工资标准的最终会计及税务口径仍以项目财务制度与合法票据为准。
