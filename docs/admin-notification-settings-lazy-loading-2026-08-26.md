# 后台通知通道设置按需加载记录

超级管理后台的短信与服务号通知通道配置仅在“系统设置”工作区使用，原先却作为 `AdminPage` 顶层静态依赖加载。现已将其改为 `React.lazy` 独立分包，并在系统设置中保留局部加载提示；权限、配置查询、密钥托管、保存和服务端校验逻辑均未改变。

| 构建指标 | 拆分前 | 拆分后 | 变化 |
|---|---:|---:|---:|
| `AdminPage` 原始分包 | 1,151,726 B | 1,132,889 B | -18,837 B |
| 通知通道独立分包 | 内联 | 20,206 B | 仅进入系统设置后下载 |

定向后台首屏依赖测试与完整 `pnpm verify:release` 均通过。标准构建仍提示 `AdminPage` 主分包超过默认体积阈值，以及自建服务器 CJS 构建的既有 `import.meta` 兼容提示；两者均未在本次修改中改变运行时行为，后续应在独立工作区迁移时继续拆分，而不应以不安全的手工分包规则掩盖依赖边界。

正式服务器已按 `release/current` 原子切换发布；应用服务保持 active，当前发布包中可确认存在 `NotificationChannelSettings` 独立分包及“正在加载短信与通知通道配置”加载提示。历史前端分包已保留，未迁移数据库、未修改业务数据。
