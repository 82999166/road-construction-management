# 实施与验证说明

## 2026-07-25：劳务工资跨项目一致性

工资草稿原先以“人员 + 工资期间”查找已有记录。已调整为“人员 + 项目 + 工资期间”，并同步数据库唯一索引为 `payroll_worker_project_period_unique`。这可以避免同一人员在不同项目的同一结算期间互相覆盖工资历史。

## 2026-07-25：真实数据态限制

数据库计数查询显示当前尚未录入项目、劳务人员、考勤或工资条业务数据。为遵循不制造模拟业务数据的约束，移动端劳务工资页只验证了无授权项目的真实空状态。录入对话框、证照文件实际上传、统计与打印完整数据态，应在超级管理后台创建真实项目、配置项目数据范围并录入真实授权业务数据后复测。

## 2026-07-25：实名审核状态接入方案

劳务人员表已新增 `pending`、`verified`、`rejected` 三种实名审核状态，以及审核备注、审核时间和审核人员字段。移动端不回显任何身份证原文，仅展示审核状态和非敏感审核结论；服务端在标记“已核验”时要求人员档案已存在身份证密文，并记录当前操作人员和时间。

移动端实名人员卡片已同时展示实名审核状态和进退场状态；编辑对话框提供待核验、已核验、核验退回三种选择及最多 500 字的非敏感审核备注。敏感身份证、手机和银行卡字段仍只显示服务端生成的掩码。
